Deterministic Verification

Why Static Rules Fail on PostgreSQL

PostgreSQL query planner decisions depend heavily on table cardinality, correlation statistics, and memory buffers. Theoretical index recommendations fail in production without empirical measurement.

Traditional Blind DBA Tools

STATIC GUESSWORK
  • Guesses index impact without execution: Leaves engineers blind to whether PostgreSQL planner will even choose the index.
  • Bloats storage with unused indexes: Proposes redundant indexes that degrade write latency on INSERT/UPDATE workloads.
  • Requires production write access or dangerous locks: High risk of table lockouts during maintenance windows.

Argus-PG Empirical Sandboxing

MATHEMATICALLY PROVEN
  • 100% Empirically Measured in Sandboxes: Runs real EXPLAIN (ANALYZE, BUFFERS) to prove the planner chooses the index.
  • Discards Negligible Candidates Automatically: If an index doesn't meet the speedup threshold (e.g. 5x+), it is pruned silently.
  • Strict Read-Only Connection to Production: All experiments, schema clones, and synthetic data live exclusively in Docker.
System Architecture

5-Stage Autonomous Engine

From production workload observation to non-blocking migration scripts in seconds.

01. OBSERVE

Telemetry Ingestion

Connects to read-only replica, introspecting pg_stat_statements and pg_class table sizes.

READ-ONLY REPLICA
02. NORMALIZE

AST Fingerprinting

Normalizes raw SQL queries into parameterized AST trees with sqlglot, stripping sensitive literals.

PII REDACTION
03. HYPOTHESIZE

Dual Brain Model

Generates compound and partial index candidates via heuristic rule engine or optional Gemini 3.5-flash.

HEURISTIC + AI
04. SANDBOX

Synthetic Hydration

Spins up ephemeral Docker container, clones catalog DDL, and hydrates 50,000 synthetic rows matching schema types.

EPHEMERAL DOCKER
05. DECIDE

Verification Gate

Compares execution cost & buffer hits. Emits non-blocking CREATE INDEX CONCURRENTLY.

Zero-Risk Guarantees

Enforced Safety Boundaries

Engineered from day one to operate safely in enterprise and mission-critical production environments.

Strict Read-Only Connection

Argus connects to your database with read-only catalog introspection credentials. It never creates tables, temporary objects, or indexes on your live cluster.

Ephemeral Docker Isolation

All database mutations, DDL executions, and synthetic row hydrations occur inside dedicated ephemeral containers that are purged immediately after testing.

Zero Data Privacy Exposure (PII Redaction)

Argus only extracts schema definitions and query AST structures. Actual user data records are never sent to LLMs or stored on disk.

Non-Blocking DDL Output

Every validated index recommendation is generated with CREATE INDEX CONCURRENTLY and accompanied by rollback statements to avoid table locking.

Get Started in 3 Minutes

Run Argus-PG Locally

No cloud accounts or credit cards required. Run it directly as a developer CLI against your local Docker environment or staging replica.

1. Clone & Install

Install via Poetry with Python 3.11+ and Docker running locally.

# Clone repository
$ git clone https://github.com/SpaceCypher/argus-pg.git
$ cd argus-pg
# Install dependencies
$ poetry install

2. Audit Database or Check Query

Inspect your database or validate an ad-hoc SQL query with automated sandbox testing.

# Audit production / replica catalog
$ poetry run argus audit
# Test specific query with sandbox validation
$ poetry run argus check query.sql --brain gemini
# Launch Mission Control Web UI
$ poetry run argus dashboard
